EchoSign Project Overview

Generated on 2026-08-22
Project Type: Accessibility / Sign-language communication platform
Frontend: React + Vite
Backend: Express + Node.js
AI Providers: Gemini and Claude
Database Support: MongoDB + PostgreSQL (optional / fallback-safe)

1. Frontend

The frontend is a React application built with Vite. It manages the end-user experience across the landing page, authentication flow, persona selection, and dashboard modules.

Main frontend entry points:

  • src/main.jsx mounts the React app to the page.
  • src/App.jsx controls the screen flow: landing → auth → persona → dashboard.
  • src/index.css contains the global design system, color palette, gradients, grid background, and animations.

Key UI components include:

  • Landing.jsx — landing page with hero and CTA
  • Hero.jsx — marketing hero section
  • Navbar.jsx — top navigation
  • Dashboard.jsx — main app shell with sidebar and tabs
  • PersonaSelection.jsx — module/persona chooser
  • Auth.jsx, EmailAuth.jsx, FaceAuth.jsx, VoiceAuth.jsx — auth UI
  • CameraView.jsx, HandTracker.jsx — webcam and sign-detection support
  • ChatPanel.jsx — AI assistant interface
  • Practice.jsx, Translator.jsx, Emergency.jsx — feature modules

Standalone HTML mock pages were also created for direct access:

  • index.html
  • modules.html
  • Live Conversation & AI Assistant.html

2. Backend

The backend is an Express app written in Node.js. It exposes APIs for login, persona selection, and AI chat responses. It also enforces CORS and privacy middleware around the application routes.

Main backend file:

  • server.js — Express app, route definitions, AI integration, and app startup

Responsibilities:

  • Handle authentication
  • Generate JWT tokens
  • Connect to AI providers
  • Protect sensitive data using privacy firewall logic
  • Optionally save activity logs to database

3. API layer

The backend exposes these core endpoints:

  • POST /api/auth/login
    • Accepts user identifier and auth type
    • Matches a sample account or creates a fallback user
    • Returns token, user profile, and sample accounts
  • POST /api/user/persona
    • Returns persona configuration based on the selected category
  • POST /api/ai/chat
    • Routes the message to Gemini or Claude depending on persona
    • Uses role-specific instructions
    • Falls back to demo text if API keys are unavailable

AI providers used:

  • Google Generative AI (Gemini)
  • Anthropic AI SDK (Claude)

4. Environment variables

The runtime configuration is stored in .env.

  • PORT=5001 — backend port
  • NODE_ENV=development — dev environment
  • CLIENT_ORIGIN=http://localhost:5174 — frontend origin for CORS
  • VITE_API_BASE_URL=http://localhost:5001 — frontend API base URL
  • VITE_INFERENCE_URL=http://localhost:8000 — inference service URL
  • JWT_SECRET=... — signing key for auth tokens
  • GEMINI_API_KEY=... — real Gemini key
  • ANTHROPIC_API_KEY=... — real Claude key
  • INFERENCE_SERVICE_URL=http://localhost:8000 — local ML/vision service endpoint

When real keys are not set, the app falls back to predefined responses instead of failing at runtime.

5. Servers and runtime

Project runtime is split into two main servers:

  • Frontend server: Vite dev server
  • Backend server: Express API server

Verified local development setup:

  • Frontend: http://localhost:4173
  • Backend: http://localhost:5001

There is also an optional inference microservice referenced at http://localhost:8000 for vision/MediaPipe tasks.

6. Database setup

The app is designed to support both MongoDB and PostgreSQL, but it gracefully falls back when those services are not configured.

  • MongoDB: Mongoose-based connection via MONGO_URI
  • PostgreSQL: pg Pool connection via POSTGRES_URI

If they are not active, the app logs warnings and continues operating in demo mode. This keeps the project stable during testing and initial setup.

8. Core application purpose

EchoSign is meant to support accessibility and inclusive communication by translating, interpreting, and facilitating sign-language interactions in real time. The UI modules target conversation, learning/practice, translation, and emergency assistance workflows.

9. Summary

This project is a full-stack accessibility application combining a modern React interface, Express REST API, optional database persistence, and AI-powered communication features. It is built for demo, development, and expansion into a real sign-language assistance platform.
